# 六地区数据管线说明

## 核心原则

1. **地区真值 = Cloudflare 官方 trace 的 `colo=` 机场码**。对候选 IP 发起 TLS（SNI=cloudflare.com）并请求 `/cdn-cgi/trace`，`colo=HKG` 才是 HK，`NRT/KIX/FUK` 才是 JP，以此类推。硬编码 CIDR 贴标签、把接入机房当出口地区，都不允许。
2. **UNKNOWN 永不发布**。能连但 colo 不属于六地区、或读不到 colo 的候选，进 `audit.json` 的 `unknown_sample` 观察区，不进数据文件。
3. **四概念分开记录**（`audit.json` 每行字段）：
   - `colo`：接入机房（trace 验证）
   - `worker_runloc`：`not_applicable`（部署事实，与数据无关）
   - `role`：`candidate_entry`（候选入口 IP）
   - `exit_ip`：`not_observed_by_pipeline`（出口 IP 只有 Worker 运行时能观测，管线绝不冒认）

## 数据来源

唯一上游：`https://www.cloudflare.com/ips-v4`（官方 IPv4 段列表）。
采样后逐 IP 做 TLS trace 探测。`pipeline/sources.json` 声明来源与机场码映射。

## 数据文件格式

`data/<REGION>.txt`：

```
# <REGION> region candidates — generated by pipeline/update_data.py
# meta_updated=2026-11-20T01:07:20Z source=https://www.cloudflare.com/ips-v4 ...
# format: address|region|source|first_seen|last_checked|status
103.31.4.1|us|colo-probe|2026-11-20T01:07:20Z|2026-11-20T01:07:20Z|OK
```

每行带数据来源、首次发现、最近检测、状态。空地区写 `# EMPTY — NOT fabricated`。

## 更新机制（GitHub Actions）

- `cron: '0 * * * *'` 每小时 + 手动触发（可调 `probe_limit`）。
- `concurrency: cfip-regions-update, cancel-in-progress`：并发锁，杜绝多 workflow 抢推。
- **保底不回退**：源获取失败（RC=2）时保留全部旧数据，仅 `::error` 显式报错；旧条目复检失败才淘汰；某轮全灭时（RC=1）数据文件不覆盖。
- 失败一律 `::error`/`::warning` 注释 + Step Summary 表格，无静默失败。
- 提交消息带 `[skip ci]`，只 `git add data/`。

## Anycast 事实声明

入口 IP 的 colo 由**探测方网络路径**决定（BGP anycast），不保证 NekoBox 用户从
其网络连接同一 IP 落同一机房。因此节点标签 `CF-US-…` 的语义是"**入口 colo 已验证为
US（EWR）**"，不是"出口 IP 在美国"。出口地区只有 F 级真机测试才能确认。
